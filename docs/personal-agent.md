# Folio 的个人 Agent 场景

企业给每个人发来同一份登记表。用户把空表交给 Folio；个人简历、项目记录和已确认的填写偏好留在个人空间里，供这次和之后的任务使用。

## 交互中的三个细节

### 表格是这次的事，资料是长期积累

首页直接展示收到的原表，以及可用的个人资料。选择表格后带入本次任务，用户可以在发送前修改要求；原表可以单独查看。首页没有预设的完成率或虚构待办状态。

资料文件与用户明确保存的个人记忆分别呈现。记忆在后端仍可作为可引用的文档参与查找，前端不将它再当成一份上传资料重复展示。

### 记住怎样表达这个人

用户可以保存“项目经历控制在100字以内，保留具体工作和结果”之类的偏好。首页显示实际保存的内容；后续任务由主 Agent 读取记忆，再按需要查资料。对话中只有用户明确要求记住时才写入记忆。

这让两份表格可以共享个人信息和表达习惯，同时保留各自的填写要求。

### 留下可继续处理的结果

结果卡片按实际报告展示写入项数、引用资料数和缺项数。用户可以逐项打开原文依据，也可以点“补充信息”填写缺项。确认后保存为一份补充资料，并带回同一对话继续原表；补充资料同样能被引用。多次补充按序号保留。

资料冲突按系统指令留空并报告；来源引用由工具校验原文位置与引用文本。资料查证、复杂模板审查按需要委派只读子 Agent，用户可在处理过程中查看。

## 演示顺序

1. 首页查看个人简历等文件，保存一条填写偏好。
2. 选择企业登记表，查看原表，编辑这次要求并发送。
3. 查看生成文件及引用的原文，保留原表结构。
4. 结果有缺项时点击补充，在当前对话继续交代。
5. 开始新对话，上传另一份表格：资料和记忆仍在。

浏览器验收使用 `tests/ui_server.py` 的脚本模型；正常工作台使用用户配置的模型服务。
